# Swarm F: original/native/WASM placed-object differential

Base: PR #45, `e32387449850b8ea2ffb93b77a48110b7b65ab65`.
This is an additive F-owned verification leaf. Local Codex retains application,
avatar, terrain and audio work. No shipping simulation or original library is
rewritten, and no root dependency, workspace or protocol contract is changed.

## Purpose and acceptance boundary

Compare the real original placement methods with the shipping Rust world layer
for ground-level geometry, collision, floor restrictions and recovery after a
rejected relocation. Use the same physical inputs and compare every field of an
explicit observation schema; never turn native=WASM agreement alone into an
original-engine claim.

The cohort has **authored object definitions and geometry**, not complete original
objects. It does not invoke the normal installed Content initialization. The
original Content singleton and global-resource cache are explicit fixture seams,
as in #44/#45; VM, context, architecture, entity, thread, room-map, obstacle and
placement implementations remain original. No placement algorithm is copied.

The actual original #44 VM/BHAV and #45 interpreter differential are still run
unchanged by the inherited workflow. This new cohort does not replace or inflate
their original-content coverage.

## Inputs and common physical semantics

`fixtures/reference/placement-cases.tsv` is a fixed, hash-pinned matrix of 24
cases. Each case is evaluated in TS1 and TSO, at north/east/south/west, yielding
192 observations. The native placement module is mode-independent; repeating it
under both labels compares that same implementation against the corresponding
original modes. It is not two separate native VMs or proof of mode-dependent
avatar behavior.

The lot is 8x8, ground floor. Two non-avatar objects start at (40,40,1) and
(88,56,1), in source sixteenth-tile coordinates, facing north. Original TileWidth
16 / FootprintMask 0 corresponds to a declared native square footprint spanning
[-8,8] in both axes. A regular floor, water and pool occupy tiles (3,5), (5,5)
and (6,5). Rooms and spatial indexes in the original are generated by the actual
architecture code, not installed as fabricated collision answers.

Cases cover free ground, self placement, touching edges, overlap, a blocker,
floor/terrain restrictions, water/pool permission and required-location flags,
ground-height prohibition, missing required wall/diagonal, explicit intersection
allowance, and negative/right-side out-of-bounds coordinates. Each case records
its required source placement-error code. That column is an assertion contract;
**neither runtime driver reads it to generate its observation**.

For each independent case, the driver:

1. Queries the candidate location and records whether query observables changed.
2. Attempts the relocation and records status, blocker, both actual positions,
   orientation and entity count.
3. Restores default physical flags, relocates the mover to (40,72,1), then retries
   the blocked cell. The latter must still reject and preserve the recovered pose.

C# calls `VMEntity.PositionValid` and `SetPosition`, including the real
`VMMultitileGroup.ChangePosition` failure/registration path. Rust calls the
shipping `validate_placement`, then an explicit **test-host** policy applies
`WorldState.move_object` only on success. `move_object` is a trusted state update,
not a standalone authorization/placement validator. This does not qualify the
production Buy/Build transaction, server admission, debit or receipt provider.

Original query purity checks the two poses, physical flags, RNG and entity count;
native query purity compares its complete `WorldState`. These are deliberately
labelled different implementations of the scoped common observation, not an
assertion that complete C# state equals a Rust snapshot. No simulation ticks are
run in this placement phase; the original RNG must remain unchanged.

## Comparison, repeatability and negative controls

The strict version-1 TSV has 25 fields: case/mode/facing; query and commit status
and blocker; query-purity flag; the two poses; entity count; successful recovery;
and blocked-retry result/final pose. All 192 keyed rows must be present in exact
order. The comparator rejects malformed, partial, duplicate, reordered,
out-of-range or noncanonical integers/line endings before equality. It validates
original-reference physical invariants first, so two identically wrong or empty
outputs cannot pass.

Normal execution runs twice each in fresh original C# processes, native Rust
processes and WASM workers. Every common field is compared with no tolerances,
result filtering or special-casing of a platform disagreement. Repeat traces and
cross-language traces must have identical bytes after explicit Windows CRLF-to-LF
transport normalization.

Two separately compiled Rust test-driver variants create actual defects at the
`collision / TS1 / north` case:

- Remove the blocker from the real world: the first mismatch must be
  `query_status`, expected 10, actual -1.
- Apply a real state update despite rejection: the first mismatch must be
  `after_x`, expected 40, actual 88.

Each fault is run natively and as WASM. These are execution/state interventions,
not altered log cells. Source libraries remain unchanged. A valid empty WASM
module must fail before emitting a trace; the original executable must refuse
execution before initialization without its explicit test-only environment flag.

The host checks WASM imports, memory, pointer/length bounds, repeat reads and a
worker deadline. Output creation is exclusive. Those limits are not total
process-memory or OS network-sandbox guarantees. Original legacy dependencies
remain reference-only; successful verification is not permission to deploy them.

## Reproduction and evidence

The Windows original-VM workflow first builds the actual ten-project dependency
graph using #44's isolated targeting references, and runs the unchanged earlier
gates. It then invokes:

```sh
python -B -S tools/replay/run_placement.py --root <exact-temporary-source> \
  --output <new-placement-evidence-directory>
```

The new runner requires that prepared original build. Rust uses the repository's
unchanged 1.99.0 toolchain, locked shipping `sim-core`, and separate native/WASM
probe binaries outside the source tree. Only fixture/control code is in the
probe. The original witness reuses #44's test-only driver and binds against the
actual freshly built VM assembly and declared runtime dependencies.

Standalone validator regression command:

```sh
PYTHONDONTWRITEBYTECODE=1 python -B -S tests/parity/test_placement_compare.py
```

Evidence contains command exit codes, all stdout/stderr, exact input and
executable hashes, loaded original CLR/VM/entity identity, actual WASM
Node/V8/module identity, normal/fault traces, first-difference records and an
aggregate `execution.json`. Parent workflow source-identity and source-after
records bind the complete source inputs to the tested Git revision before and
after every run. Retained artifacts contain text evidence, not game assets,
fonts, binaries or restored dependency directories.

## Implementation ledger and verification status

- Validator tests were written first. An always-pass stub incorrectly admitted
  changed collision/rollback observations and equal-but-wrong references. Those
  behavioral failures were observed before implementation; absent parser API
  errors in that initial run are setup errors, not behavioral RED proof.
- The final local validator suite passed 13 tests. Local shipping-library native
  and real WASM executions emitted 192 matching rows (14,438 bytes); all four
  actual fault variants were detected at the intended first field.
- Local compilation used a recovered compiler/registry archive and source inputs
  independently matched to PR #45's retained Git-source identities, not a fresh
  complete network checkout. The relevant 102 sim-core and 306 original
  SimAntics files matched; .NET Framework is unavailable locally.
- Original C# placement execution and the published checkout's complete gate are
  therefore **pending at initial publication**. Final hosted results and exact
  revision will be recorded in the PR; local native/WASM agreement alone is not
  original placement equivalence.

## Remaining qualification

Higher floors/support, non-square/multi-tile groups, actual walls/doors, slopes,
SLOT/container handling, scripted intersection, avatars, route selection and
complete installed global/semiglobal/tuning/patch cohorts remain separate tests.
Real authenticated players, durable effects/costs, full replicated state,
rendered-browser/device/load behavior and release qualification are not covered
by these authored ground-placement observations. No merge, deployment or
independent code-review approval is claimed.
