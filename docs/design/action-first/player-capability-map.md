# Player capability preservation map

All 21 original player surfaces remain in scope. The redesign keeps the Sim, map and lot as the main places to act. It adds a connected browser client and source rendering alongside the existing preview; it does not authorize removing legacy features or replacing an account with a fixed set of identities.

A capability is complete when its controls, source data, permissions, rendering and accepted/rejected behavior work together. This map records the current implementation and names the remaining work. A command encoder, unavailable-state panel or passing fixture test is not full gameplay parity. See the [connected integration handoff](connected-integration.md) for startup, source pins, verification and the distinction between source snapshots and the deterministic runtime.

**Reading the last column:** **Code** means an adapter or control is still missing from this repository. **External** means an operator must supply an actual service, account or original resource. Both can apply to the same surface; supplying assets alone does not implement missing code. Evidence references identify inspectable implementation and tests in the index below. Final combined verification is recorded in the handoff, separately from these coverage references.

## Original rules and preservation boundaries

The inspected original server enforces three account avatars in `TSOClient/FSO.Server.Database/DatabaseScripts/changes/0001_3_max_avatars.sql`. A chosen service may have a different policy; the browser must use that service's result and must not discard returned Sims or invalidate existing preview saves. Resource limits and page sizes are not new game limits.

The original creator submits head outfit, body outfit, gender, skin, name and description independently. The wardrobe uses owned records for Day/Sleep/Swim and head/back/shoes/tail decorations. Whole-character illustrations are not replacements for those choices.

Verified functional Buy categories include Seating, Surfaces, Appliances, Electronics, Skill, Decorative, Misc, Lighting and Pets. Room-sort controls are declared, but working behavior was not established by the source inspection. House Statistics/Bills/Log are explicitly disabled in the inspected original. Those qualifications remain separate from newly missing adapters.

Lot geometry, stories, object capacity, ownership and prices come from source world/runtime/service state. Some Build categories place objects; others submit architecture commands. Source snapshot `VMTSOLotState.LotID` is a packed map location, not database lot ID or Home owner. Reusable short ObjectIDs and local presentation generations do not become authoritative entity identities.

Existing preview roster, cafe, map, Home, outfits, possessions, budget and versioned saves remain available in explicit Preview mode. The connected entry point does not open or rewrite those saves. Original `TSOClient` and `Other` remain the preserved reference implementation. The [scope correction](preservation-scope.md) and [earlier preservation plan](../../superpowers/plans/2026-10-05-preserve-game-capabilities.md) remain historical context; this map and the connected handoff describe the current integration boundary.
